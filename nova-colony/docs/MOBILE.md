# Nova Colony — Mobile build, store setup & release guide

The game is a TypeScript/Vite web app packaged for iOS and Android with **Capacitor 8**
(`appId com.novacolony.game`, `appName Nova Colony`, `webDir dist`). Native plugins are used for
storage (Preferences), rewarded ads (AdMob), purchases (RevenueCat), haptics, splash/status bar and
app lifecycle. **Every plugin is loaded lazily and only inside the native shell**, so the plain web
build (`npm run dev` / `npm run build`) never needs them.

| Concern | Web / dev | iOS / Android (Capacitor) |
|---|---|---|
| Storage | `localStorage` (memory fallback if blocked) | `@capacitor/preferences` |
| Rewarded ads | clearly labelled **DEV AD** overlay (3 s countdown) | `@capacitor-community/admob` |
| Purchases | `confirm()` "DEV STORE" mock | `@revenuecat/purchases-capacitor` |
| Analytics | console sink (dev) / HTTP sink if configured | same |
| Haptics | no-op | `@capacitor/haptics` |
| Cloud save | optional HTTP backend | same |

Code lives in `src/platform/*` (adapters, `SaveManager`, analytics hooks) and `src/sim/liveops.ts`
(ad limits, shop, daily/spin/season logic). The native projects are in `android/` and `ios/`.

---

## 1. Prerequisites

- Node 20+ and `npm ci` in `nova-colony/`.
- **Android**: JDK 21 and the Android SDK (`compileSdk`/`targetSdk` 36, `minSdk` 24; AGP 8.13 + the bundled Gradle 8.14.3 wrapper). Android Studio (Narwhal 3 / 2025.1.3 or newer) is optional: see *Building Android locally* below for a command-line-only setup.
- **iOS** (macOS only): Xcode 16+. The iOS project uses **Swift Package Manager** (no CocoaPods).
  Min deployment target is set by Capacitor 8 (iOS 15).
- Accounts: Apple Developer Program, Google Play Console, AdMob, RevenueCat.

## 2. Build & run

```bash
cd nova-colony
npm ci
npm run build              # tsc + vite build -> dist/
npx cap sync               # copy dist/ into android/ and ios/, update native plugins
npx cap open android       # Android Studio -> Run
npx cap open ios           # Xcode -> select a team -> Run
# or straight to a device/emulator:
npx cap run android
npx cap run ios
```

`package.json` scripts: `cap:sync` (build + `cap sync`), `cap:android` / `cap:ios` (sync, then open the IDE) and the
command-line Android builds `android:sync`, `android:debug`, `android:lint`, `android:release`
(see *Building Android locally* below).

**Live reload on a device** (web changes without rebuilding the native app):

```bash
npm run dev                                   # vite on :5173
npx cap run android -l --external --port 5173 # or: npx cap run ios -l --external --port 5173
```

Run `npx cap sync` again whenever you add/upgrade a Capacitor plugin or change `capacitor.config.ts`.
Files generated by `sync` (`public/` copies, `capacitor.config.json`, `config.xml`) are git-ignored.

### Building Android locally

Verified end to end on a headless Linux box (no Android Studio, no emulator), 2026-10-07:
JDK 21, Gradle 8.14.3 (the project's `gradlew` wrapper downloads it), AGP 8.13.0, Kotlin plugin 2.2.20.

**1. Install the SDK once** (anywhere outside the repo; the three packages below are all Capacitor 8 needs,
`compileSdk 36` + AGP's default build-tools, about 0.5 GB):

```bash
export ANDROID_HOME=$HOME/android-sdk        # or /opt/android-sdk
mkdir -p "$ANDROID_HOME/cmdline-tools"
# "commandlinetools-linux-<n>_latest.zip": current <n> is listed in https://dl.google.com/android/repository/repository2-3.xml
# (16111833 = cmdline-tools 23.0 when this was written; mac: commandlinetools-mac-<n>_latest.zip)
curl -LO https://dl.google.com/android/repository/commandlinetools-linux-16111833_latest.zip
unzip -q commandlinetools-linux-*_latest.zip -d /tmp/clt && mv /tmp/clt/cmdline-tools "$ANDROID_HOME/cmdline-tools/latest"
yes | "$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" --licenses     # newer tools may ask while installing instead
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" "platform-tools" "platforms;android-36" "build-tools;36.0.0"
```

Installed that way: `platform-tools` (adb), `platforms;android-36`, `build-tools;36.0.0` (aapt2, apksigner, zipalign).
Tell Gradle where the SDK is with `export ANDROID_HOME=…` **or** a one-line `android/local.properties`
(`sdk.dir=/abs/path`, git-ignored: never commit it).

**2. Build** (from `nova-colony/`, after `npm ci`):

```bash
npm run android:debug      # tsc + vite build -> cap sync android -> ./gradlew assembleDebug
npm run android:lint       # ./gradlew lintDebug (0 errors; the remaining warnings come from Capacitor's template)
npm run android:release    # build + sync -> ./gradlew bundleRelease (unsigned unless signing is configured, see §6)
cd android && ./gradlew assembleRelease     # same, but an APK for side-loading tests
```

On Windows run the Gradle steps with `gradlew.bat`. `npm run android:sync` does only the web build + `cap sync android`.

**3. Outputs** (all under the git-ignored `android/app/build/`):

| Artifact | Path | Size (Oct 2026) |
|---|---|---|
| Debug APK | `outputs/apk/debug/app-debug.apk` | ~19 MB (install with `adb install -r …`) |
| Release APK (unsigned) | `outputs/apk/release/app-release-unsigned.apk` | ~16.6 MB |
| Release AAB (unsigned) | `outputs/bundle/release/app-release.aab` | ~16.3 MB |
| Lint report | `reports/lint-results-debug.html` | |

Most of the size is the un-minified AdMob/Play-services dex (R8 is off: `minifyEnabled false`; turn it on only
together with an on-device smoke test of ads + purchases). The web game itself is ~6.4 MB (`dist/`, incl. 142 art files).

Notes:

- The first build downloads Gradle, the Android dependencies and Kotlin (a few hundred MB, cached in `~/.gradle`). If Maven
  Central answers **429 Too Many Requests** (shared proxy/CI egress), just re-run: Gradle keeps what it already fetched;
  `--max-workers=2` lowers the request burst.
- The plugin modules are built in place, so `node_modules/@capacitor*/**/android/build/` appear (ignored by git).
  `./gradlew clean` removes them.
- `cap sync` rewrites `android/capacitor.settings.gradle` and `ios/App/CapApp-SPM/Package.swift`. The committed
  files use the canonical `../node_modules/...` paths. If `node_modules` is a **symlink** (e.g. a git worktree sharing one
  `node_modules`) sync writes the symlink target instead (`../../../../../nova-colony/node_modules/...`), which breaks every
  other checkout: restore with `git checkout -- android/capacitor.settings.gradle ios/App/CapApp-SPM/Package.swift` before committing.

Quick web smoke test of the platform layer: `npm run dev`, open the console and run
`await game.sys.liveops.watchAd('production_boost')` (shows the DEV AD overlay) or
`await game.sys.liveops.buy('nova_crystals_small')` (DEV STORE confirm).

## 3. Environment variables

Vite exposes `VITE_*` variables at build time. Put them in `nova-colony/.env.production` (or your CI
environment). **They are bundled into the app, so only use public identifiers here — never secrets.**

| Variable | Purpose | If unset |
|---|---|---|
| `VITE_ADMOB_REWARDED_IOS` | AdMob rewarded ad unit id (iOS) | Google **test** unit — never serves live ads |
| `VITE_ADMOB_REWARDED_ANDROID` | AdMob rewarded ad unit id (Android) | Google **test** unit |
| `VITE_ADMOB_TESTING=true` | Force test ad requests even with real ids (use on QA builds) | real ads once ids are set (test ads in `vite dev`) |
| `VITE_RC_IOS_KEY` | RevenueCat **public** SDK key (Apple app, starts with `appl_`) | iOS store disabled, shop falls back to "unavailable" |
| `VITE_RC_ANDROID_KEY` | RevenueCat public SDK key (Google app, starts with `goog_`) | Android store disabled |
| `VITE_ANALYTICS_URL` | HTTPS endpoint receiving analytics batches (see §8) | events are dropped; nothing leaves the device (console sink in dev) |
| `VITE_CLOUD_SAVE_URL` | Base URL of the optional cloud-save backend (see §7) | cloud saves unavailable |
| `VITE_APP_VERSION` | Reported in analytics batches | `0.1.0` |
| `VITE_DISABLE_WEB_IAP=true` | Make **web** builds report the store as unavailable (use for a public web deployment) | web shows the DEV STORE mock |

Native-only (not Vite) settings:

| Setting | Where | Default |
|---|---|---|
| AdMob **Android app id** | `-PADMOB_APP_ID_ANDROID=ca-app-pub-…~…` Gradle property (or `android/gradle.properties`) → manifest placeholder in `android/app/build.gradle` | Google test app id `ca-app-pub-3940256099942544~3347511713` |
| AdMob **iOS app id** | `GADApplicationIdentifier` in `ios/App/App/Info.plist` | Google test app id `ca-app-pub-3940256099942544~1458002511` |

> **PLACEHOLDER ids: replace before store submission.** Both AdMob *app* ids above, and the rewarded *unit* ids
> compiled in as fallbacks (`src/platform/ads.ts`), are Google's documented **sample/test** ids (the `3940256099942544`
> publisher). They are **not ours**: they serve test ads only and earn nothing. They are shipped on purpose so a fresh
> checkout can build and run (the AdMob SDK **crashes at launch** if the manifest has no `APPLICATION_ID`, so the Android
> manifest always carries one) and can never serve live ads by accident. The RevenueCat keys have no placeholder: unset means
> "store unavailable".

## 4. Store products (IAP) to create

The product ids below come from `src/data/monetization.ts` (`PRODUCTS`) and **must be identical on the
App Store and Google Play**. Prices in the game always come from the store at runtime (localized);
the "fallback" column is only shown on web / when the store is unreachable. Set the real prices in each
store's price tier — the game never hard-codes them.

| Product id | Type | Fallback price | Grants | Limit |
|---|---|---|---|---|
| `nova_starter_pack` | Non-consumable | $0.99 | 300 Nova, starter resources, Pioneer outfit | 1 per account |
| `nova_crystals_small` | Consumable | $4.99 | 500 Nova | — |
| `nova_builder_pack` | Consumable | $9.99 | 1,100 Nova + 2 h 2× production boost | — |
| `nova_colony_pack` | Consumable | $19.99 | 2,400 Nova | — |
| `nova_commander_pack` | Consumable | $49.99 | 6,500 Nova | — |
| `nova_ultimate_pack` | Consumable | $99.99 | 14,000 Nova | — |
| `colony_pass_monthly` | Auto-renewing subscription (1 month) | $7.99 / mo | VIP "Colony Pass" 30 days | — |
| `season_pass_premium` | Non-consumable | $9.99 | Premium track of the current season | 1 per season |

If you edit `PRODUCTS`, mirror the change in both stores and in RevenueCat, then re-test.

> **Fair-play rule:** nothing in the game is locked behind payment. Purchases grant Nova, boosts,
> cosmetics, convenience and the premium *season track* only. Keep it that way.

### RevenueCat setup

1. Create a project; add an **Apple App Store** app (bundle id `com.novacolony.game`) and a **Google Play** app (package `com.novacolony.game`). Upload the App Store Connect / Play service credentials.
2. Under *Product catalog → Products*, add every id above for each store. (Entitlements/offerings are optional: the game purchases store products directly with `purchaseStoreProduct`.)
3. Copy the **public** SDK keys (`appl_…`, `goog_…`) into `VITE_RC_IOS_KEY` / `VITE_RC_ANDROID_KEY`.
4. Restore: players can tap *Restore purchases* (`game.sys.liveops.restorePurchases()`); non-consumables re-grant only their entitlements (cosmetics, season premium), never duplicate currency; the subscription expiry is synced into the VIP timer on launch and every 30 minutes (renewals).

### Store configuration

- **iOS**: in App Store Connect create the products (consumable / non-consumable / auto-renewable subscription in a subscription group) and add the **In-App Purchase** capability in Xcode (*Signing & Capabilities*). Test with a Sandbox tester.
- **Android**: in Play Console create *In-app products* (managed) and one *Subscription* with a monthly base plan, activate them, and upload at least an internal-testing build before purchases work. Add License testers.

## 5. AdMob (rewarded ads)

Ads are **always optional and rewarded** — no banners, no interstitials. Placements and limits are data
(`AD_PLACEMENTS` in `src/data/monetization.ts`): `offline_double` (primary), `production_boost`,
`instant_craft`, `free_crate`, `recruit_refresh`, `invasion_bonus`, `research_bonus`, `extra_spin`,
`drone_assistant`. Daily limits and cooldowns are enforced in `LiveOpsSystem.canWatchAd`.

1. In AdMob create an **iOS** app and an **Android** app, then one **Rewarded** ad unit in each.
2. Set the two ad unit ids via `VITE_ADMOB_REWARDED_IOS/ANDROID`.
3. Set the **app ids** (not unit ids): Android via the `ADMOB_APP_ID_ANDROID` Gradle property, iOS in `Info.plist → GADApplicationIdentifier`. The repo ships Google's **test** ids so a fresh checkout can never serve live ads.
4. **SKAdNetworkItems** in `Info.plist` already holds Google's complete AdMob list: **50 identifiers** (`cstr6suwn9.skadnetwork`, Google's own, first), copied on 2026-10-07 from <https://developers.google.com/admob/ios/3p-skadnetworks> (page "Last updated: January 30, 2026"). Google adds networks over time: re-check that page before each release and append any new id (the page has no downloadable file, only the table).
5. Configure the **consent message** (GDPR/UMP) and, if you target children, the child-directed settings, in AdMob → Privacy & messaging. The adapter requests consent info and shows the form when required, and requests iOS App Tracking Transparency lazily right before the first ad (`NSUserTrackingUsageDescription` is set in `Info.plist`).
6. Publish `app-ads.txt` on your developer website domain (listed in the store listing).
7. For QA builds with real ids use `VITE_ADMOB_TESTING=true` and register your device as a test device in AdMob. **Never click your own live ads.**

While an ad is showing the game is paused; if the ad service never answers, the call times out after 2 minutes and the game resumes. A skipped/failed ad gives nothing and does not use up the daily limit.

## 6. Native project notes

- **Orientation**: portrait + landscape. iOS `UISupportedInterfaceOrientations` has Portrait + both Landscapes (iPad: all four); Android `screenOrientation="fullUser"` (follows the user's rotation lock).
- **Android manifest** permissions declared by us: `INTERNET`, `ACCESS_NETWORK_STATE`, `VIBRATE` (haptics), `com.android.vending.BILLING`, `com.google.android.gms.permission.AD_ID` (declare advertising-id use in the Play *Data safety* form). The merged release manifest adds, from libraries only: `ACCESS_ADSERVICES_AD_ID` / `_ATTRIBUTION` / `_TOPICS` (AdMob / Privacy Sandbox), `WAKE_LOCK` (Google Mobile Ads measurement), `FOREGROUND_SERVICE` (WorkManager, pulled in by the ads SDK) and a signature-level `<applicationId>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` (androidx.core). All are install-time/normal permissions with no runtime prompt; nothing location/contacts/storage/camera related. `allowBackup="true"`: Android Auto Backup restores the Preferences-stored save when the player moves to a new phone.
- **WebView / hardening** (checked in the merged manifest + `capacitor.config.ts`): `android:hardwareAccelerated="true"` on the activity (WebGL needs it), no `usesCleartextTraffic` (so HTTPS-only at targetSdk 36), `allowMixedContent: false`, `androidScheme: https`, our own `android:exported` is limited to the launcher activity (the few exported library receivers/services, e.g. WorkManager's and the Amazon IAP receiver that RevenueCat bundles, are permission-protected), no `debuggable` in release. Background colour `#1b2a3a` is the same everywhere: `capacitor.config.ts` (`BACKGROUND`, SplashScreen/StatusBar/ios/android), `res/values/colors.xml` → Android 12+ system splash (`windowSplashScreenBackground` in `styles.xml`), the splash art's bottom colour, `index.html` / `manifest.webmanifest`.
- **iOS** `Info.plist`: `GADApplicationIdentifier`, `NSUserTrackingUsageDescription`, `SKAdNetworkItems`, `ITSAppUsesNonExemptEncryption=false`, `UIRequiredDeviceCapabilities=arm64`.
- **System font size (Android)**: `MainActivity` pins the WebView's `textZoom` to 100. The game scales its whole UI to the screen; Android would otherwise also zoom every label by the accessibility font scale and the HUD/panels overflow at large font settings.
- **Splash & status bar**: the splash hides as soon as the game is ready (`src/platform/hooks.ts`; `capacitor.config.ts` keeps a 2.5 s auto-hide as a safety net). The status bar is hidden for an immersive full-screen game.
- **Icons / splash art**: Nova Colony's own art is in place (adaptive launcher icon at all five densities + round icon, portrait/landscape splashes, iOS 1024² icon and splash), generated by `art/generate.mjs` (`art/icon.svg`, `art/splash.svg`). The hero (planet, dome, pod) is the painted Higgsfield art in `art/source/app-icon/` (body + smoke layers), composed into `art/icon-painted.svg`; delete that folder to fall back to the vector hero in `icon.svg`. Edit the sources and re-run the generator rather than the PNGs. iOS 18 dark and tinted home-screen icons are supplied too (`AppIcon-dark.png`: the hero on transparency; `AppIcon-tinted.png`: the glyph, white on black). Android 13+ themed icons are supported: the adaptive icon has a `monochrome` layer (`ic_launcher_monochrome`, a flat glyph from `art/source/app-icon/monochrome.png`, sized inside the 66dp safe zone by the generator).
- **Versioning**: bump `versionCode`/`versionName` in `android/app/build.gradle` and `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` in Xcode for every upload.
- **Signing (Android)**: release signing is opt-in and keeps secrets out of the repo. Without configuration `bundleRelease`/`assembleRelease` produce an **unsigned** artifact (fine for CI and size checks, not uploadable). To sign:
  1. Create the upload key once and back it up somewhere safe (losing it means a Play support request):
     `keytool -genkeypair -v -keystore nova-colony-upload.jks -alias nova-upload -keyalg RSA -keysize 2048 -validity 10000`
  2. Put the four values in `~/.gradle/gradle.properties` (never in the repo) or in CI environment variables:
     `NOVA_UPLOAD_STORE_FILE=/abs/path/nova-colony-upload.jks`, `NOVA_UPLOAD_STORE_PASSWORD`, `NOVA_UPLOAD_KEY_ALIAS=nova-upload`, `NOVA_UPLOAD_KEY_PASSWORD` (defaults to the store password). `android/app/build.gradle` picks them up.
  3. `npm run android:release` → `android/app/build/outputs/bundle/release/app-release.aab`; check with `jarsigner -verify -verbose -certs app-release.aab` (or `apksigner verify` for an APK).
  4. Enrol in **Play App Signing** on the first upload; Google then re-signs with the real app key and your upload key only authenticates uploads.
- **Signing (iOS)**: set the Team in Xcode and *Product → Archive* (macOS only).

## 7. Saves, backups & recovery (never lose progress)

`SaveManager` (`src/platform/save.ts`, attached by `main.ts` after `game.start()`):

- **Autosave** every `balance.autosaveSeconds` of play, whenever the app is hidden/paused (browser `visibilitychange`/`pagehide` and Capacitor `App` pause), and ~1.5 s after valuable moments (purchase, ad reward, daily claim, tier-up).
- **Checksummed writes** (`NCS1:<crc32>:<json>`); a torn write is detected on load.
- **3 rotating local backups**, one every 5 minutes (compressed). If the main save is corrupt, load falls back to the newest backup that validates and heals the main slot; the corrupt payload is kept under `nova_colony_save_corrupt` for support.
- A structurally broken in-memory state is **never written over a good save**.
- **Versioned migrations**: bump `SAVE_VERSION` (`src/core/constants.ts`) and register `MIGRATIONS[oldVersion]` in `src/platform/saveMigrate.ts`. New fields are filled with defaults automatically.
- **Recovery codes**: `game.saves.exportRecoveryCode()` → text the player can store anywhere; `game.saves.importRecoveryCode(code)` validates (checksum, structure), backs up the current save, writes the import, suspends saving (so the running game cannot overwrite it) and **reloads the app ~1.5 s later** so the restored colony loads (`new SaveManager(services, { autoRestart: false })` to do it yourself with `restart()`). Failures return `false` and set `game.saves.lastError` (readable text). `listBackups()` / `restoreBackup(slot)` power a "Restore from backup" list. The attached manager is available as `game.saves`, `window.saves` (used by the Settings panel) and `activeSaveManager()`.
- **Unclaimed "Welcome back" earnings** are kept in the save until claimed (`liveops.pendingOffline`), because `Game.start()` resets the offline clock: quitting at that screen never loses them, and leftovers are merged into the next summary.
- **Cloud save** (optional): set `VITE_CLOUD_SAVE_URL`. The device gets a random **recovery id** (`NOVA-XXXX-XXXX-XXXX`, shown via `game.saves.cloudRecoveryId()`; enter it on another device with `setCloudRecoveryId`). Protocol:
  - `GET  {base}/{id}` → `200` + body (a recovery code) or `404`
  - `PUT  {base}/{id}` with `Content-Type: text/plain` and the recovery code as the body → any `2xx`
  - the id is a bearer secret (60 random bits): serve over HTTPS, rate-limit, and cap the body (~1 MB).
  - Upload happens at most every 3 minutes and when the app is backgrounded. At boot the save with the larger `playTime` wins (the loser is backed up first), with a 4 s timeout so an offline start is never delayed.

## 8. Analytics & privacy

Privacy-conscious by construction (`src/platform/analytics.ts`, `analyticsHooks.ts`):

- **Opt-in/out** follows `settings.analytics` live (checked every second). Nothing is recorded or queued while it is off; turning it off deletes the queue **and the install id**.
- **No PII**: only game facts (mission ids, tiers, counts, durations). Strings are length-limited and e-mail-like strings are redacted. The only identity is a random 128-bit install id (not a device id, not the advertising id).
- **Batched** in memory (20 events / 30 s / on pause), failed sends are retried with a bounded queue.
- **Sink**: `VITE_ANALYTICS_URL` receives `POST` JSON:
  `{ v: 1, installId, session, platform, appVersion, events: [{ name, props, ts }] }` (`keepalive` on pause). Without a URL, events are dropped (dev: printed to the console).
- **Events**: `session_start`, `session_end`, `quit_point` (current main mission + % when the app is paused), `retention_day`, `tutorial_step` / `tutorial_complete`, `tier_up` (with time-to-tier), `research_done`, `building_usage` (aggregated), `region_discovered`, `wave_won`, `ad_started` / `ad_rewarded` / `ad_failed`, `offline_claimed`, `shop_opened`, `iap_purchased` / `iap_failed`, `daily_claimed`, `season_level`, `progression_stall` (10 minutes of play without completing a mission).
- Declare accordingly in the **Apple privacy labels** ("Data not linked to you": usage data) and the **Play Data safety** form, plus advertising-id use for AdMob. Consider defaulting `settings.analytics` to off in the EEA.

## 10. Troubleshooting

| Symptom | Likely cause |
|---|---|
| App launches then crashes on Android with an AdMob message | `ADMOB_APP_ID_ANDROID` is not a valid app id (it must be the *app* id with `~`, not the unit id with `/`). |
| Rewarded ad says "No video available" | Normal for new ad units (fill takes hours) or a device without ads; test ids always fill. The game keeps working and no daily use is consumed. |
| Prices show the fallback (`$4.99`) on a device | Store products not yet approved/active, the RevenueCat key is wrong/unset, or the device is offline. |
| Splash never disappears | The hook that hides it runs from `SaveManager.attach`; make sure `main.ts` still calls `saves.attach(game)`. The 2.5 s auto-hide is the fallback. |
| `cap sync` removes my manifest edits | It does not: only generated files are rewritten. Check you edited `android/app/src/main/AndroidManifest.xml` / `ios/App/App/Info.plist`. |
| Gradle: `SDK location not found` | Set `ANDROID_HOME` or create `android/local.properties` with `sdk.dir=/abs/path` (see *Building Android locally*). |
| Gradle: `Could not GET https://repo.maven.apache.org/… 429` | Rate limiting by the network between you and Maven Central. Re-run (cached downloads are kept), optionally with `--max-workers=2`. |
| `Warning: SDK processing. This version only understands SDK XML versions up to 3…` | Harmless: the command-line tools are newer than AGP. |
| Gradle can't find `../../../../../nova-colony/node_modules/...` on someone else's machine | A `cap sync` run with a symlinked `node_modules` rewrote `capacitor.settings.gradle` / `Package.swift`; restore the canonical `../node_modules/...` files from git. |
| Recovery codes fail on an old Android WebView | The WebView lacks `CompressionStream`; codes are then produced uncompressed (`NC0-…`, longer) and can still be read by any device. |
