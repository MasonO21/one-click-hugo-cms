# Night Precinct: iOS shell

A thin native container for the game. UIKit plus one `WKWebView` that loads the bundled
`www/index.html`, StoreKit 2 purchases exposed to the page through a message bridge, a save-file
mirror, haptics and Safari links. No SwiftUI, no third-party code, no network calls of its own.

The message protocol is defined in `../docs/NATIVE_BRIDGE.md`. Product catalog, prices and data
practices are defined in `../docs/FACTS.md`. Neither is repeated here.

**Important: this code was written without a compiler.** Nobody has built it yet. Read the
"First compile checklist" below before you assume a failure is a bigger problem than it is.

## Build steps

You need a Mac.

1. **Install Xcode** from the Mac App Store. Use the Xcode version Apple currently requires for
   App Store uploads (check "Upcoming Requirements" on developer.apple.com/news; at the time of
   writing that is Xcode 26 or later with the iOS 26 SDK). Open it once and accept the license.
2. **Install XcodeGen:** `brew install xcodegen`
3. **Fill in your details once** in `release.config.json` (bundle ID, team ID, and so on), then from
   the repository root run:
   `python3 tools/apply_config.py`
   This fills the placeholders and writes `ios/project.yml` and
   `ios/NightPrecinct/Products.storekit`.
4. **Build the game into the app:**
   `python3 tools/build.py --target native`
   The result must be `game/www/index.html`. The whole `game/www` folder is copied into the app
   as a folder named `www`, so keep only what the game needs in it.
5. **App icon:** `ios/NightPrecinct/Assets.xcassets/AppIcon.appiconset/AppIcon-1024.png` is already in
   the repository (1024 x 1024 PNG, no transparency, no pre-rounded corners; iOS rounds them). To
   change the artwork edit `tools/assets/icon.svg` and run `node tools/make_assets.js icon` from the
   repository root. App Store validation rejects an icon with an alpha channel or the wrong size.
6. **Generate the Xcode project:**
   `cd ios && xcodegen generate`
7. **Open** `ios/NightPrecinct.xcodeproj`.
8. **Set your Team:** click the project, select the `NightPrecinct` target, Signing & Capabilities,
   choose your Team. The team ID from `release.config.json` is already written into the project;
   if it is still the `XXXXXXXXXX` placeholder Xcode will complain until you fix one of the two.
   Automatic signing is on. **No capabilities need to be added**: StoreKit purchases require none.
9. **Run** on a simulator or a device (Product > Run).
10. **Test purchases** (next section).
11. **Archive:** select "Any iOS Device (arm64)", then Product > Archive, then Distribute App >
    App Store Connect. Create the in-app purchases in App Store Connect with exactly the product
    IDs listed in `../docs/FACTS.md` section 3 (bundle ID, a dot, the suffix) before you test with
    TestFlight.

Any time you change `release.config.json` or a `.tmpl` file, repeat steps 3 and 6.

## Testing purchases locally

The scheme `NightPrecinct` already points its Run action at `Products.storekit`, so a run from
Xcode uses the local test store and never touches the real App Store.

- Simulator or device, launched from Xcode: buy, cancel, and restore work against the test catalog.
- Debug > StoreKit > Manage Transactions shows every purchase. You can refund, approve "Ask to
  Buy" requests and expire the subscription from there. Delete a transaction to reset a
  non-consumable and test the purchase again.
- The subscription in the test file renews weekly in real time. To speed that up, open
  `Products.storekit` in Xcode and use Editor > Subscription Renewal Rate.
- Scheme > Edit Scheme > Run > Options > StoreKit Configuration should read `Products.storekit`.
  If it says None, pick the file.
- A build installed from TestFlight or the App Store does not use this file. It talks to Apple's
  sandbox or production store and needs the products to exist in App Store Connect.

**If Xcode refuses to open `Products.storekit`:** the file was written by hand in the format
Xcode 15 and 16 produce. If Xcode rejects it, recreate it: File > New > File > StoreKit
Configuration File, name it `Products` (save it in `ios/NightPrecinct/`), then re-enter the
products from `../docs/FACTS.md` section 3 (consumables, non-consumables, and the auto-renewable
subscription in a group named "Chief's Club" with a 1-week period). The product IDs must be the
bundle ID, a dot, then the suffix.

## Where the save file lives

`Application Support/save.json` inside the app container. It is included in device backups on
purpose (FACTS.md section 2). To look at it in the simulator:

```
xcrun simctl get_app_container booted <your bundle id> data
```

then open `Library/Application Support/save.json` inside that folder.

## Debugging the page

Debug builds set `isInspectable`, so Safari's Web Inspector works: on the Mac enable Safari >
Settings > Advanced > Show features for web developers, run the app, then Develop > (your
simulator or device) > Night Precinct. Release builds are not inspectable.

## Notes for the game page author

- The web view fills the whole screen, under the status bar and home indicator. Position UI with
  `env(safe-area-inset-*)` and set `viewport-fit=cover` in the viewport meta tag.
- Set `user-scalable=no` in the viewport meta tag. Pinch zoom is disabled natively, but double-tap
  zoom is a page-level setting; also use `touch-action: manipulation`.
- The web view's own scrolling is off. Scroll inside your own containers.
- `window.open` and `target=_blank` create nothing. An `https` link the page tries to navigate to
  is opened in Safari View Controller instead, and any other navigation is cancelled.
- JavaScript `alert`, `confirm` and `prompt` are not implemented natively (WebKit silently
  dismisses them). Use in-page dialogs.
- Audio can only start after a user tap (`mediaTypesRequiringUserActionForPlayback` is left at
  its strict default).
- `window.NPNative` should provide `onTransaction(tx)`, `onBackground()` and `onForeground()`.
  All three are optional; native code checks that they exist before calling them.
- `NP_BOOT` is rebuilt from the current `save.json` for **every** load of the page, not just the
  first. That is what makes the game's own `location.reload()` after `wipe` start empty instead
  of resurrecting the old save. Reloading the page is allowed; navigating anywhere else is not.
- If the web content process is killed by iOS while the app is in the background, the shell
  reloads the page (with a fresh `NP_BOOT`) on its own.

## First compile checklist

Everything below was written and reviewed by hand. These are the places most likely to need a
small tweak. Fix in this order; most first-build failures are one of the first four.

1. **`addScriptMessageHandler(_:contentWorld:name:)`** in `GameViewController.viewDidLoad`. This is
   the reply-capable variant. If Xcode says it does not exist, look for the closest completion
   (`add(_:contentWorld:name:)` is the *non-reply* handler and will not work with the async
   protocol).
2. **`NPBridge.userContentController(_:didReceive:) async -> (Any?, String?)`.** The async form of
   `WKScriptMessageHandlerWithReply`. If Xcode reports the class does not conform, use the
   Fix button; it inserts the exact signature. Keep the body: it awaits `handle(body:)` and
   returns `(reply, nil)`.
3. **`product.priceFormatStyle.currencyCode`** in `StoreManager.productInfo`. If it is not
   accepted, use `product.priceFormatStyle.locale.currency?.identifier ?? ""` (iOS 16 API).
4. **XcodeGen output.** If `xcodegen generate` complains about a `source` entry, the two least
   standard lines in `project.yml.tmpl` are: `buildPhase: none` on `Products.storekit` (delete
   that whole source entry; the scheme reference still works) and `group: Resources` on the
   `../game/www` folder reference (delete the line). After generating, check in Xcode that `www`
   is a **blue folder** in the navigator and appears under Build Phases > Copy Bundle Resources,
   and that `Products.storekit` is **not** in Copy Bundle Resources.
5. **`decidePolicyFor` signature.** Newer SDKs declare `decisionHandler` as
   `@MainActor @Sendable`. Swift 5 mode accepts the plain closure type used here; if Xcode offers a
   "fix" that adds those attributes, accept it.
6. **Concurrency warnings.** The project builds in Swift 5 language mode with
   `SWIFT_STRICT_CONCURRENCY = minimal`, so passing `[String: Any]` between `StoreManager` (an
   actor) and the main-actor bridge should produce no diagnostics. If a newer toolchain warns
   about Sendable, that is a warning, not an error; do not raise the strictness.
7. **App icon.** A missing `AppIcon-1024.png` warns during the asset catalog step and fails
   validation at upload.
8. **`UIRequiresFullScreen`** may show a deprecation note with the newest SDK. It is intentional
   (FACTS.md: iPad full screen) and safe to leave.
9. **Empty `game/www`.** Until step 4 has produced `index.html`, the app launches to a plain
   "game files are missing" message. That is the designed failure screen, not a crash.
10. **`Storefront.current`** in `StoreManager.storefront()`. It is an async static property
   (`await Storefront.current`, iOS 15+) and `countryCode` is the ISO 3166-1 alpha-3 code
   (`"BEL"`, `"USA"`). If the compiler rejects the `await`, you are looking at the older
   `SKPaymentQueue.default().storefront` API by mistake; keep the StoreKit 2 one.

After it builds, verify at runtime: the page loads and is dark edge to edge; a purchase in the
test store returns a `tx` and the game grants once and calls `finish`; a force-quit and relaunch
mid-purchase redelivers the transaction; save, kill, relaunch restores the save; **Settings >
Erase save restarts the game empty (the erased save must not come back after the reload)**;
the Safari sheet opens for a legal link; haptics fire on a phone; with the Xcode StoreKit
configuration's storefront set to Belgium, the Store and Cases tabs show no crate purchases.

## Design notes for the reviewer

- Transactions are never finished by native code on its own initiative. They wait in an in-memory
  dictionary until the page sends `finish`. The one exception is an unverified consumable, which
  is finished at once and never reported.
- `unfinished` also fills that dictionary, and `finish` falls back to scanning StoreKit's
  unfinished queue, so a `finish` that races ahead of `Transaction.updates` after launch still
  works.
- The boot script is swapped inside `decidePolicyFor`, right before a load of the game page is
  allowed. WebKit delivers that script update to the web process ahead of the policy reply, so
  the new script is the one that runs. If a reload ever shows stale data, this is the place to look.
- The app uses no `UserDefaults`, no file timestamp, disk-space or boot-time APIs, so the privacy
  manifest declares no accessed API types. Keep it that way, or update the manifest.
- The only network traffic is StoreKit's and Safari View Controller's (which runs in Apple's
  process). There is no App Transport Security exception and none is needed.
