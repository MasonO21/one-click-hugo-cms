# appstore/: App Store Connect submission package for Night Precinct

Everything the owner needs to fill in App Store Connect (ASC) for version 1.0.0 (build 1), written from `docs/FACTS.md`, `docs/NATIVE_BRIDGE.md` and `release.config.json`, and checked against the game source (`game/src/`), `tools/apply_config.py`, `tools/build.py` and the `ios/` project. If a fact changes, change `docs/FACTS.md` first, then the files below.

Start with `SUBMISSION_CHECKLIST.md`. It has the ordered steps and a "What only you can do" list at the top.

## What is in this folder

| File | What it is |
|---|---|
| `SUBMISSION_CHECKLIST.md` | The owner's ordered steps from Apple Developer enrollment to post-release, including the test matrix. |
| `IAP.md` | The 16 in-app purchases and the Chief's Club subscription group: IDs, types, prices, names, descriptions, review screenshots, reviewer notes. |
| `AGE_RATING.md` | The age-rating questionnaire answers, the expected rating, and why the app is not for the Kids category. |
| `APP_PRIVACY.md` | The App Privacy label answers (Data Not Collected), the privacy manifest notes, and what to redo if an SDK is added. |
| `EXPORT_COMPLIANCE_AND_RIGHTS.md` | Export compliance, content rights, trademark cautions, and the documents Apple may ask for. |
| `GUIDELINE_COMPLIANCE.md` | A map from App Store Review Guideline areas to how the app complies, plus known review risks and mitigations. |
| `metadata/en-US/*.txt` | One plain-text file per ASC field: name, subtitle, promotional text, description, keywords, What's New, URLs, copyright, review notes, categories. |
| `metadata/en-US/LIMITS.md` | Character limits, the measured lengths, and a script that checks them. |
| `screenshots/` | Generated by `node tools/make_assets.js shots` (run from `night-precinct/`; needs Node, Playwright and Chromium) from the game itself, at exact App Store pixel sizes: `iphone-6.9` (1320 x 2868), `iphone-6.5` (1284 x 2778) and `ipad-13` (2064 x 2752). Six PNGs in each, RGB with no alpha: `01-hq`, `02-roster`, `03-upgrades`, `04-ops`, `05-fire`, `06-ems`. They do not show the Store tab, so the in-app purchase review screenshots (`IAP.md`) are captured separately. |

The app icon is not in this folder. `node tools/make_assets.js icon` generates it into `ios/NightPrecinct/Assets.xcassets/AppIcon.appiconset/AppIcon-1024.png` (1024 x 1024, RGB, no alpha; the copy in the repository was checked). Apple currently accepts a smaller set of screenshot sizes than the three sets above (see the checklist, step 13): **verify the required sizes in App Store Connect**.

## Tokens

The text files contain double-brace tokens (`APP_NAME`, `APP_SUBTITLE`, `BUNDLE_ID`, `COMPANY_NAME`, `COMPANY_ADDRESS`, `CONTACT_EMAIL`, `PRIVACY_EMAIL`, `SUPPORT_URL`, `PRIVACY_URL`, `TERMS_URL`, `PURCHASE_TERMS_URL`, `ODDS_URL`, `WEBSITE_URL`, `VERSION`, `BUILD`, `YEAR`), named as in `release.config.json` and `docs/FACTS.md` section 7. They are filled from `release.config.json` by `python3 tools/apply_config.py`.

- No personal name or personal email appears anywhere in this folder. Contact details are tokens.
- **`YEAR`** is used by `metadata/en-US/copyright.txt`. `release.config.json` has no `YEAR` entry and does not need one: both `tools/apply_config.py` and `tools/build.py` add `YEAR` themselves, set to the calendar year of the day you run them. If you render the text in a later year than the release year, fix the copyright line before you paste it.
- **`tools/apply_config.py` is non-destructive.** It never rewrites the source templates (`appstore/`, `legal/`, `ios/*.tmpl`). It writes only git-ignored output: `release/legal/`, `release/appstore/` (a filled-in copy of this whole folder, screenshots included), `ios/project.yml`, `ios/NightPrecinct/Products.storekit` and `game/www/index.html`. It deletes and recreates `release/legal/` and `release/appstore/` on every run, so never edit files inside `release/`; edit the sources and run it again. **Paste text into ASC from `release/appstore/metadata/en-US/`**, not from `appstore/metadata/en-US/` (the latter still contains tokens).
- A token that is not in `release.config.json` stops the script in a `.txt` file and is left as written in a `.md` file. The `.md` documents mention tokens on purpose (for example product IDs in `IAP.md`), so the copies in `release/appstore/` have your real bundle ID ready to copy.
- The character limits apply after the tokens are filled. `apply_config.py` checks them and prints `PROBLEM:` lines; `metadata/en-US/LIMITS.md` has a second script and the measured lengths.
- `python3 tools/apply_config.py --strict` renders everything and then exits with status 1 if any config value is still a placeholder (`[UPPERCASE TEXT]`, `example.com`, `yourcompany`, `XXXXXXXXXX`) or if it prints a `PROBLEM:` line. Use it as the gate before you submit. A date is not a placeholder pattern, so it does not check `EFFECTIVE_DATE`; read that one yourself.

## Conventions

- **"Verify in App Store Connect"** marks anything that depends on Apple's current policy or on what ASC shows today (questionnaire wording, screenshot sizes, SDK requirement, price points, limits, menu names). What I wrote is my understanding and may be out of date. Check it in ASC and trust ASC over this folder.
- **"verify the exact guideline number"** marks guideline numbers I am not sure of. Do not quote a number to App Review until you have looked it up.
- **"Check in build"** marks things that can only be confirmed in a running iOS build (a device, the Simulator, TestFlight or the sandbox). The game code itself has been read and run in a desktop browser; nobody has run it in a compiled iOS app yet.

## What I could and could not confirm from the game

Confirmed by reading `game/src/*.js`, `styles.css` and `markup.html`, the `ios/` files and the tools, and by running the built game in a desktop browser against a mock of the native bridge (the same kind of mock `game/tests/native-mock.js` uses), including the Store tab, the Career tab, the Settings screen and the purchase sheets. Where the game prints text, this folder uses the same words.

- **Launch and navigation.** The game opens on the Roster tab. The bottom tab bar reads HQ, Roster, Gear-Up, Cases, Store, Career. The header shows rank, cash and the Gold Badge counter with a "+"; tapping the counter opens the Store tab. The main button reads ARREST!, EXTINGUISH! or TREAT!.
- **HQ tab.** "Free Rewards" (the sub-line reads "no ads, just cooldowns"): Rally Boost (2x income for 15 minutes, ready every 3 hours), Supply Drop (a free standard crate every 6 hours), Daily Roll Call, and the **"Settings and Legal"** card ("Sound, haptics, restore purchases, privacy, terms") with an Open button. Below: Next Goal, the promotion progress bar and the ledger.
- **Cases tab.** Squad slots and timed cases (Assign), the three crates with an Open button each and buy buttons x1 and x5 (paid with Gold Badges; hidden when the device region is Belgium), a line "Pity: the top two crates guarantee Epic+ gear within 10 opens", and the **"Drop rates" button, which opens the in-app odds screen** (three tables that match `docs/FACTS.md` section 4). Then the Gear Locker.
- **Store tab, top to bottom.** Auto-Clickers card (Auto-Clicker and Combo Auto-Clicker both offered on a new save; once the Auto-Clicker is owned the card becomes an "Upgrade" card and an On/Off card appears); Rookie Starter Pack with a countdown (first 48 hours after first launch, until bought); Chief's Club card (price "/ WEEK", one-line renewal and cancellation text; when active it shows Claim 25 badges and Manage); Career Pass Premium card (until owned); Evidence Safe card ("Holds N Gold Badges (20 to 500)"); **Daily Deals** ("each can be bought once a day": Crate Trio, Cash Crate, Recruit Rush, all listed every day, "Bought today" afterwards, the crate deal hidden only in Belgium); Gold Badges (six packs, "First-time 2x"); then the Gold Badge spending sections (Boosts and Upgrades, Elite Recruits, Garage and Skyline); and a footer with **Restore Purchases, Manage Subscription, Settings** buttons, "Purchases are charged to your Apple Account. Gold Badges have no cash value. Crate odds are in the Cases tab." and links to Terms of Use, Privacy Policy, Purchase Terms and Crate odds.
- **Career tab.** Promotion, Worlds, Precinct Patron (with the spending thresholds), Daily Roll Call, Career Pass (30 tiers, Claim all, Skip tier, a Go Premium button), Service Record (achievements), and a "Settings and Legal" block with Open Settings and Restore Purchases.
- **Settings screen** (from the HQ card, the Career tab or the Store footer): Sound, Haptics and Reduce flashing switches (Reduce flashing starts on when iOS Reduce Motion is on), Restore Purchases, Manage Subscription, Privacy Policy, Terms of Use, Purchase Terms, Crate odds, Support, Credits and Erase save (two taps). Privacy Policy, Terms, Purchase Terms, Crate odds and Support open the hosted pages in the Safari view; Crate odds there is the web page, not the in-app screen. Credits says the game is fiction and links to the notices page.
- **Purchase sheet.** Every purchase first opens the game's own "Confirm purchase" sheet: item name, price, what you get, a "Buy for <price>" button (the subscription reads "Buy for <price> / week" and adds the renewal paragraph), Cancel, and links to Terms of Use, Privacy Policy and Purchase Terms. Apple's payment sheet comes after that.
- **Copy and mechanics.** A promotion resets crews, upgrades and cash and keeps Medals, Badges, gear, recruits, cosmetics and purchases; Medals are a permanent income bonus. Without Chief's Club, offline earnings pay 50% with a 2 hour cap (raised to 4, 8 or 24 hours by Overtime Pay upgrades bought with Gold Badges). Chief's Club pays 100% with a cap of at least 8 hours.
- **No ad SDK, no demo checkout, no analytics.** Searched in `game/src` and `ios/NightPrecinct`: no ad, analytics, crash-reporting or other third-party code, no `fetch`, XHR, WebSocket or beacon calls, no cryptography, no `UserDefaults` and no file-timestamp, disk-space or boot-time APIs. The release build carries a Content Security Policy with `connect-src 'none'`, so the page cannot open network connections. `Info.plist` has no permission strings and sets `ITSAppUsesNonExemptEncryption` to false; `PrivacyInfo.xcprivacy` declares no tracking, no collected data and no required-reason APIs.
- **Refunds.** When Apple refunds a one-time unlock (the Auto-Clicker levels, Career Pass Premium), the game removes the unlock and shows a message. Consumables that were already spent are not taken back, and neither is the content of the Starter Pack or the Precinct Patron spend total.

Not confirmed, and not claimed anywhere in this folder: that the Swift code compiles (`ios/README.md`: "Nobody has built it yet"), anything about StoreKit against Apple's sandbox or TestFlight, the layout on a real device, and everything that lives in App Store Connect.

The EMS world uses a heartbeat (ECG pulse) mark on the ambulances and in the medic portraits, and a heart emblem for the world. No red cross, red crescent or Star of Life is used (and none may be added). See `EXPORT_COMPLIANCE_AND_RIGHTS.md` section 3.

## Statements in the listing that go beyond `docs/FACTS.md`

Some statements in the listing are not in `docs/FACTS.md`. Guideline 2.3 (accurate metadata; verify the exact guideline number) means every claim must be true in the shipped game. Each one below was checked against the game source. If the game changes, edit `metadata/en-US/description.txt` too.

- "Promote to the next rank: crews, upgrades and cash reset, but Medals boost your income for good." Verified (`promote()` and the promotion screens): a promotion resets crews, upgrades and cash, and gives Medals, each a permanent income bonus.
- "Hire crews that keep earning when you are not tapping", "buy upgrades that multiply your income", "send squads out on timed cases and chase bounty targets". Verified: Roster, Gear-Up and Cases tabs; a running bounty character appears every few minutes and is tapped to catch.
- "Offline earnings are waiting when you come back (50% pay, 2 hour cap to start)". Verified (`offlineFor`, `offlineCap`, and the "Off-duty earnings" screen, which shows the rate).
- "Free to download" (the app price is set to Free in ASC; the owner sets it).
- "Buying crates with Gold Badges is turned off in Belgium" and the odds being "shown in the app". Verified: `crateBuyAllowed()`; the odds are in the Cases tab (Drop rates) and behind the Crate odds links in Settings and the Store tab.
- "4.99 USD per week" for Chief's Club (keep in sync with the ASC price).
- In `review_notes.txt`: the Store tab holds every purchase, and the Gold Badge counter also opens it; the "Settings and Legal" card holds Settings; Settings holds Restore Purchases, Manage Subscription and the legal links (Purchase Terms, Crate odds and Support included); the odds are in the Cases tab; the subscription purchase screen shows the price, "per week", the benefits, the renewal and cancellation text and the Terms, Privacy and Purchase Terms links. All verified. The "Manage" and "Claim" buttons on the Chief's Club card and the Restore Purchases button in the Store footer are described as they are.
- In `IAP.md`: the Evidence Safe card and its purchase sheet show the amount before purchase (verified). The offers that contain crates (Crate Trio, Rookie Starter Pack, Career Pass Premium) show the odds of the crate tiers they contain on their purchase sheet; the full table is on the Cases tab ("Drop rates") and in Settings.

## Open points in the build

Found while verifying the docs against the game. Items that were code problems have been fixed in the game (the Career tab price now comes from StoreKit, every offer that contains crates shows the odds on its purchase sheet, the offer is worded "Elite crates", the EMS art has no cross marks at all, the local StoreKit test names match `IAP.md`, and `build.py --out` no longer touches `game/www`). What is left is a judgment call for you:

1. **No Restore button on the Chief's Club purchase sheet.** Restore Purchases is in the Store tab footer (the same tab as the Chief's Club card), in Settings and on the Career tab. That satisfies the requirement; add a button to the sheet if you want it closer.
2. **The 25 daily Chief's Club badges are a manual "Claim" button**, not automatic. The listing says "25 Gold Badges every day", which is accurate, but reviewers may expect it to be delivered without a tap.
3. **The Precinct Patron card shows US dollar values.** They are the fixed reference values described in `docs/FACTS.md` (and labelled as such in the game), not what Apple charged in your storefront.
4. **Screenshots** are rendered from the web build (see step 13 of the checklist). A recent set has no transient banners and no price chips; regenerate with `node tools/make_assets.js shots` after any art or layout change.
5. **The description and release notes contain the "•" bullet character.** Everything else in this folder is plain ASCII. App Store Connect accepts it.

## Index of every item marked "Verify in App Store Connect"

Age rating (`AGE_RATING.md`)
- Exact wording and scale of every questionnaire question, including in-app controls, capabilities, medical or wellness, violence, chance-based activities.
- Whether an Advertising question exists, and whether there is a separate loot-box question or a spending question.
- The rating Apple calculates (I expect 9+, possibly higher because of the loot-box answer), regional ratings, and any age-assurance requirements.
- The Kids-category guideline number (1.3 as I know it).

App Privacy (`APP_PRIVACY.md`)
- Field names on the App Privacy page and Apple's current definition of "collect".
- The list of data-type categories, including newer ones.
- Whether Apple wants crash logs shared through Xcode Organizer listed (I say no).
- Which required-reason APIs need a declaration in the privacy manifest (the shell uses none that I could find; Apple's list changes).

Export and rights (`EXPORT_COMPLIANCE_AND_RIGHTS.md`)
- The export-compliance wording, the exemption, the annual-report point, and the France declaration.
- Whether the content-rights answer for OFL fonts should be No (my answer) or Yes.
- The attorney and trademark check of the name (the EMS art itself uses no protected medical emblem).
- Which documents Apple requires for your account and storefronts, including EU trader documents, EULA choice and game licenses.

In-App Purchases (`IAP.md`)
- Whether a deleted product ID can be reused (I believe not), and whether Family Sharing can be switched off again (I believe not).
- Which USD price points exist (4.79 and 9.59 for the auto-clickers), and the auto-equalized prices in other storefronts.
- Tax category, promotional image requirement, review screenshot size and whether one screenshot can serve several products.
- That the first products are submitted together with the app version.
- Whether the Evidence Safe presentation is acceptable.
- The subscription group's custom app name field and limit, billing grace period defaults, subscription review-notes limit, and the 3.1.2 guideline sub-letters.
- The IAP guideline number for reachable, complete products (2.1 as I know it).

Metadata limits (`metadata/en-US/LIMITS.md`, `metadata/en-US/categories.txt`)
- Maximum lengths of the Support URL, Copyright, Subscription Group Display Name and Product ID.
- All the limits in the table, in general (ASC's live counter is the authority).
- The category and subcategory options, the two-subcategory rule, and whether a Games app may use Games as its secondary category.

Guidelines (`GUIDELINE_COMPLIANCE.md`)
- Every sub-number (1.1, 1.3, 1.4, 1.5, 2.3.x, 2.4, 2.5.2, 3.1.1, 3.1.2, 4.1, 4.2, 4.2.6, 4.3, 5.1, 5.2, 5.3).
- The loot-box odds sentence's guideline number (3.1.1 as I know it).
- South Korea, mainland China and EU requirements.

Checklist (`SUBMISSION_CHECKLIST.md`)
- The current required Xcode and SDK version (I believe Xcode 26 with the iOS 26 SDK from April 2026; `ios/README.md` says the same).
- The Developer Program fee and the agreements menu name.
- EU trader status and the details shown on the store page.
- The In-App Purchase capability default on the App ID.
- How long a reserved app name is held.
- EULA choice (Apple standard or custom).
- Content-rights answer.
- Sandbox tester menu, the sandbox sign-in path on the device, product loading conditions, subscription renewal speed and count, and Ask to Buy testing.
- Screenshot sizes and which sets are required. The generated sets are iPhone 6.9-inch (1320 x 2868), iPhone 6.5-inch (1284 x 2778) and iPad 13-inch (2064 x 2752); Apple currently accepts a smaller set of sizes, so check which of them ASC asks for.
- App price Free, and availability: Belgium, mainland China, South Korea, other regions, and automatic availability in new regions.
- Review submission button names, typical review time, phased release (updates only), and consent for subscription price increases.
- Low-storage handling (the shell reads no disk-space API, so no manifest entry is expected).
- IDFA question.
